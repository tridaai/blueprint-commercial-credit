# Changelog — Commercial Credit Memo & Covenant Monitoring Agent

## 1.0.0 — 2026-10-30

The blueprint at v1.0: the full twenty-round build, frozen by a
release-hardening pass (R20) that set the version, wrote this
changelog and the release notes from the record, swept the
README and architecture notes for claims that no longer matched
the release state, and re-ran every gate on the finished tree —
the full test suite with the Postgres parity profile live, the
eval gate including its Postgres legs, the demo end to end, and
the production smoke. The exact freeze figures are recorded in
`docs/release-1.0.0.md`.

The gaps that remain are stated in the README's Honest status
and are unchanged by this release: there is no real LOS or
core-banking integration (ports and a reference feed only);
document extraction is the offline reference extractor over the
generated borrower documents, and the model gateway's live
profiles are real adapters exercised against stub transports —
no live provider key has been used, and drafting defaults to
the offline profile; the risk-rating scorecard is a coded
stand-in for a validated bank model, shipping the plumbing and
the discipline around a model rather than the model; nothing
in this system approves credit — the committee gate is the end
of the line, and its decisions are records for the bank's own
process; the S3 document store is verified to its port (the
compose stack's SeaweedFS has not been run end to end); and
the Docker image build and compose stack are verified by
inspection only — this build environment has no Docker daemon,
so no run is claimed. Round 17's access control is an
application-level policy, not an identity provider: a
deployment still puts its own authentication in front of the
service. The README's work-in-progress notice stays on:
hands-on developer testing and the companion blog post are
still outstanding.

### The twenty rounds

- **R1 — Core.** The credit file model (borrower, guarantors,
  facility request) behind a store port; an LOS intake port
  with a reference feed; document checklists generated by
  facility type, every item citing the policy rule that
  required it; document intake through an S3-compatible port
  with SHA-256 recorded at intake and re-verified on every
  read; provenance-carrying extraction — every value carries
  its document, page and line, and a value without complete
  provenance is rejected whole batch, in code; the audit log,
  structured JSON logs with request ids, and `/health` /
  `/readiness`, the readiness payload naming the live store
  profile. The sample borrower (Hartline, a mid-market
  manufacturer) is seeded here.
- **R2 — Spreading engine.** The bank's statement template as
  data; every extracted value mapped onto its template line
  across all periods at once. Unmapped lines are carried as
  named entries, never dropped or folded into a line they do
  not belong to. Multi-period spreads (FY2022–FY2024) in
  Decimal, deterministic — the same inputs rebuild the same
  spread byte for byte. Adjustments as first-class records
  (coded + free-text reason, provenance, proposer; an
  incomplete adjustment is rejected), the unadjusted view
  never touched; restatements supersede cleanly with the new
  version recorded.
- **R3 — Computation engine.** The full ratio set defined in
  writing — liquidity, leverage, coverage (DSCR, fixed-charge
  coverage), profitability, cash flow — computed in code from
  the spread; EBITDA with its working shown. Every figure is a
  derivation chain whose inputs name the spread line, period
  and extraction provenance; a verifier re-performs the
  arithmetic, and the eval gate requires 100% trace
  completeness. Global cash flow combines borrower and
  guarantors with eliminations as named records. Computation
  packs are content-addressed; a figure whose inputs are
  absent is recorded *not computable*, naming what is missing
  — nothing zero-filled (the sample borrower's EBITDA names
  depreciation & amortisation, absent from its statements).
- **R4 — Policy pack.** Lending policy as versioned code:
  eight coded tests, each citing the policy it encodes —
  leverage by segment, minimum DSCR (borrower and global),
  fixed-charge coverage, single-borrower concentration,
  required-documents completeness, statement and appraisal
  age limits — each with blocker/warning severity. A third
  outcome, *not evaluable*, names the missing input; a DSCR
  the statements cannot support is never a silent pass, and
  the gate's silent-pass counter is required to be zero.
  Evaluation pins one pack version, recorded in the file's
  policy history; reports are stored, content-addressed
  artefacts. Two versions ship — v2 tightens DSCR to 1.35×,
  hospitality leverage to 1.75× and statement age to 15
  months; a borrower at 1.30× passes v1, fails v2, and its v1
  report stays on the record untouched.
- **R5 — Memo drafting + figure verifier.** A structured
  draft memo (migration 0005), content-addressed, its header
  pinning the spread, computation pack, policy pack + version,
  policy report and as-of date by id. The figure verifier
  traces every numeric figure in the rendered text and tables
  to a pinned artefact, a spread value, a policy threshold or
  a stated file fact — one untraceable figure refuses storage,
  with the offenders named; the clearing traces are stored as
  the memo's verification record. The exceptions section must
  account for exactly the pinned report's non-pass outcomes,
  structurally. Drafting sits behind a profile port: the
  deterministic offline composer ships; a live profile is
  defined behind the same port, unconfigured. The memo states
  facts; the recommendation is the officer's.
- **R6 — Credit officer gate.** The first human gate. Every
  action names its actor and role; approving, returning and
  flagging require an officer role, mechanically. Approval
  mints an officer-final memo — it never edits the draft in
  place — and edited text faces the figure verifier again
  before anything is stored; the exceptions section is locked
  at this gate. Every approval records its diff (migration
  0006): section-level and figure-level changes, an as-is
  approval recording an empty diff. Returns are coded
  (`officer-return-reasons-v1`), a returned memo reopens
  nothing — it is recomposed into a superseding draft — and
  an officer may flag for committee attention or declare a
  conflict of interest that bars them from approving.
- **R7 — Committee gate.** The second human gate, where the
  credit itself is decided. A decision (migration 0007) names
  its members and the quorum they met — at least two,
  mechanically, so no sole approver exists — and the recorder
  must be a member. Outcomes approve / approve with
  conditions / decline / defer, each carrying only its own
  payload. Conditions are structured records whose covenant
  thresholds must trace through the verifier's universe.
  Declines carry coded ECOA reasons
  (`adverse-action-reasons-v1`), each mechanically tied to a
  failed or not-evaluable policy test, a traced figure, or a
  missing checklist item — a reason on the wrong evidence is
  refused, and there is no free-text reason field; the
  borrower-facing notice is generated from the codes and
  ties. Deferrals carry coded reasons and named
  re-presentment requirements. Status remains derived from
  the event stream, never stored.
- **R8 — Disagreement handling.** Borrower figures arrive
  from typed sources — audited statements, tax return,
  management statements — and the types never merge:
  supersession runs within a source type, and a later tax
  return stands beside the audit as a different witness. A
  versioned disagreement policy (`aldergrove-disagreements`
  v1) sets precedence (audited, then tax, then management)
  and tolerances; beyond tolerance the spread records a
  Disagreement — every source's value with full provenance,
  deltas, and a materiality verdict — and nothing is ever
  averaged. Figures computed over materially disagreed lines
  are flagged through their derivation chains, across the
  global pack too. The memo gains a Document disagreements
  section rendered by one canonical function the verifier
  requires verbatim; the section is locked at the officer
  gate. The seed borrower gains its tax return and management
  accounts: seven disagreements, five material, graded
  exactly. No migration — disagreements are content of the
  spread artefact.
- **R9 — Committee readiness.** One consolidated
  ReadinessReport (migration 0008) per file: every required
  input with its state — present fresh, present stale (age +
  breached limit), missing, or not-evaluable input naming the
  missing source. Three requirement sources are consolidated:
  the facility checklist, the policy pack's age limits, and
  the computation pack's not-computable figures. Freshness
  limits are data — read from the pinned policy pack and a
  versioned readiness policy (`aldergrove-readiness` v1) —
  never constants. The committee convene recomputes readiness
  fresh and refuses while any blocker stands, naming every
  blocker; officer approval carries the report id and blocker
  count, so the block is on the record early. There are no
  waivers — the surface is proven absent; a blocker clears
  only when the input itself refreshes. The borrower-facing
  outstanding-items list is generated from the blockers.
- **R10 — Covenant model + scheduler.** Covenants are clocks
  + math. A committee approval creates the covenant set
  (migration 0009) from the decision's own traced covenant
  conditions and the policy pack's standard template for the
  facility type — the committee's term governs duplicates,
  and a condition whose cadence cannot be scheduled refuses
  the decision before anything is stored. Test dates derive
  from the recorded closing date (a named, audited file fact;
  a change is a named correction); a set created before
  closing stands `awaiting_closing_date` — no anchor is
  guessed. The schedule is derived in code (month-lattice
  arithmetic, capped at maturity, final test at maturity),
  every instance standing in a derived state, `awaiting_inputs`
  naming exactly what it waits for. An idempotent scheduler
  tick records first sightings once; the due-work queue
  answers across the portfolio. Amendments mint the next
  covenant version with a coded reason
  (`covenant-amendment-reasons-v1`) and the authorising
  decision — no in-place mutation surface exists.
- **R11 — Covenant test execution + breach cases.** Due
  tests re-spread the period through the R2 engine and
  recompute through R3 — no new math. Results are
  content-addressed, insert-once artefacts (migration 0010)
  with honest outcomes: pass / fail / not_evaluable /
  awaiting_inputs, the blocked states naming what they wait
  for, a not_evaluable never reading as a pass. A failing
  test opens its BreachCase in the same act — a failure
  without a case cannot exist — carrying the figure, the
  threshold and a cure deadline. The case state machine runs
  on coded acts by named officers: cured only by a later
  passing re-test of the same covenant, waived only on a
  stored committee approval of the same file, escalated and
  defaulted under coded reasons
  (`breach-resolution-reasons-v1`); terminal states refuse
  every further act, and nothing is deleted or silently
  closed. Restated periods derive a
  `superseded_by_restatement` standing at read time.
- **R12 — Annual review.** Every approved facility owes a
  review twelve months after closing (or after approval,
  the basis named — never guessed) and annually to maturity;
  instances derive in code (month-lattice arithmetic, leap
  years exact), join the due-work queue, and are opened by
  the tick idempotently; a late review never pushes the next
  one out. The review pack (migration 0011) is assembled in
  code from stored artefacts only: the spread rebuilt and
  figures recomputed on the latest statements, covenant
  history with restatement standing, breaches with their
  resolution state, disagreements carried as R8 left them.
  Policy runs twice — under the decided memo's pinned version
  and under the current version — with every per-test
  difference surfaced. Readiness is recomputed at the review
  date; an incomplete pack is produced and marked, naming
  every blocker. The review summary's locked facts are
  rendered by code and the composer's narrative passes the
  figure verifier, which recomputes the locked record: a
  dropped or reworded fact, an invented figure, or a breach
  denied in prose is refused. Outcomes are coded stances
  (`annual-review-reasons-v1`); the memo's approving officer
  may not affirm alone (a countersigning officer is required),
  and an escalation mints a committee referral in the same act.
- **R13 — Risk-rating scorecard.** `aldergrove-scorecard` as
  data: seven factors with inputs, band thresholds and
  weights summing to exactly 1, grade bands covering 1–10
  exactly once; a definition that does not validate is
  refused at registration, and a registered version is never
  silently replaced. An assignment (migration 0012) is a
  content-addressed artefact recording every factor's input
  value and trace, band, score and weighted contribution; a
  figure that cannot compute scores its named missing-data
  band — never zero-filled. The rating is an input, never a
  decision: the memo header and the review pack's locked
  record carry it, and the gates neither import nor consult
  the scorecard — graded identical behaviour on rated and
  unrated files. Overrides move the final grade at most one
  grade, for a coded reason (`rating-override-reasons-v1`),
  countersigned by a different officer, as their own artefact
  beside the unedited assignment; a chain cannot walk the
  grade away. History is append-only, and cross-version
  comparisons are labelled as such. Stated in the round
  itself: a coded stand-in for the bank's validated model.
- **R14 — Officer console.** One static HTML file served at
  `/console` — inline CSS and vanilla JS, no build step, no
  external assets — rendering the pipeline queue (files
  grouped by their derived stage, with fresh readiness blocker
  counts, current ratings, open breach counts), the due-work
  board (breaches, covenant tests and deliverables, annual
  reviews, worst first), and the file workspace in
  credit-officer order. The console decides nothing and writes
  nothing of its own: its action forms post to the existing
  gated routes with the officer's name and role from the
  identity bar, a form will not submit anonymously, and a
  refusal renders once as a plain-language error. The codes
  its forms offer are served from the gates' own vocabularies.
  Rendering is treated as a security property: every node is
  built with `createElement`, every stored string assigned
  through `textContent` — no HTML-parsing sink anywhere — and
  the suite and the eval gate scan the page (every path
  literal a declared route, every declared route real, no
  action under `/console`, exactly one `fetch` call site).
- **R15 — Model gateway.** The one configured path every
  model call goes through. Profiles are data, loaded
  fail-closed (`data/model_profiles.json`): `offline` (the
  deterministic composer), `hosted-frontier` (Anthropic
  Messages API), `in-boundary` (an OpenAI-compatible endpoint
  inside the bank's boundary) — a profile names its model and
  the *variables* holding endpoint and key, never a key value;
  a duplicate id, an unpriced model, or a live profile missing
  its endpoint or key variable refuses the whole configuration,
  and the deployment's profile must resolve at startup or the
  stack does not start. There is no fallback: an unknown or
  unconfigured profile refuses and none is substituted. The
  model polishes narrative only — tables and structured parts
  never pass through it, a reply that does not parse back is
  refused whole, and what survives faces the same verifiers
  as the offline draft. Every call is priced and ledgered in
  an append-only ledger (migration 0013) *before* any verifier
  runs — a refused draft is still ledgered at its exact price;
  offline calls ledger at $0. Budgets are enforced before
  transport: at the per-file cap, live calls refuse before any
  transport is touched, recorded as a budget event and surfaced
  as 429; the gateway never switches profiles by itself.
- **R16 — Postgres production profile, verified.** The whole
  suite runs against real Postgres 16 with outcome parity: a
  parity harness (`tests/pg_parity.py`, keyed by
  `CREDIT_TEST_DATABASE_URL`) swaps every test double for the
  real `PostgresCreditStore` — a fresh, fully migrated schema
  per instance — and fails loudly if a named server is
  unreachable rather than quietly testing the doubles. The
  thirteen migrations are graded on a fresh database (UTF8,
  template0): apply-all, then apply-none, then a read-back
  through a second store instance. A production smoke boots
  the API on a fresh database and walks one credit file
  through the whole lifecycle over HTTP, 21/21 steps. With
  `CREDIT_EVAL_DATABASE_URL` set, the eval gate grades the
  migrations, the smoke steps and the parity gap; without a
  URL the checks are skipped and the skip is counted — never
  silent. The compose stack already matches the production
  shape (Postgres 16 + pgvector, SeaweedFS); what is *not*
  verified is stated in the round: the Docker image build and
  the compose stack itself, inspection only, no daemon.
- **R17 — Injection defences + retrieval access control.**
  Borrower text stops being trusted. A deterministic
  instruction-pattern scanner (quarantine pack `2026.10.1`,
  as data) runs over every document at ingestion, field by
  field at its JSON path — the filename too, separators read
  as spaces — recording quarantine events with the
  sentence-exact span and any figures inside it; documents
  are never rejected, evidence is evidence, and abbreviation
  stops never end a span early, so a dictated figure cannot
  be cut out of the record by punctuation. On every model
  surface, quarantined spans are fenced — replaced by a
  marker naming the pattern and carrying no figure. A planted
  figure grounds nothing: refused at extraction, struck from
  the memo verifier's trace universe, so an injected statement
  leaves extraction, spread, computation and memo
  byte-identical to the clean run, modulo the document's own
  hash chain. A named officer's quarantine review is recorded
  and never un-fences. Retrieval stops being open: one access
  module with a versioned role policy (`2026.10.1`) — five
  roles over fourteen artefact families, whole-book vs
  assigned scope, assignment itself a recorded act. Existence
  hiding (a 404 byte-identical to a nonexistent file), coded
  403s, the read-only role refused by middleware before any
  gate logic, and every refusal recorded as an access-denial
  record. The gate grades the full role × family × scope
  matrix. Stated boundary: an instruction split across two
  fields so no single field matches is a boundary of the
  pattern approach.
- **R18 — Eval depth.** The gate walks the lines themselves:
  every figure threshold in the policy pack graded at exactly
  its value and one quantum (0.0001) either side — DSCR,
  leverage ceilings including one segment's own, fixed-charge
  coverage, global DSCR — with each fixture's figure checked
  against its hand value first; age limits graded at their
  month and one past, under both pack versions. The deeper
  grading exposed a real defect, fixed in this round: **the
  concentration limit was judged on the rounded share** — the
  facility's share of the capital base was quantized to four
  places before comparison, so amounts whose true share
  exceeded the 10% limit by less than half a display quantum
  passed (at the stated capital base, up to $25,012,499). The
  comparison now reads the unrounded share; the display is
  unchanged, and when rounding would have hidden a difference
  the outcome's detail names the unrounded share. Also
  graded: staleness edges and the one-stale-input file (its
  blocker named, its refresh alone clearing the convene), the
  cure clock at its deadline (overdue only strictly after),
  adverse-action probes (a reason tied to a test the report
  does not contain, a figure misstated by one cent, a code on
  the wrong test — refused), a census re-reading every stored
  committee decision, disagreement provenance re-performed
  source by source to 100%, and the R17 injection planted
  inside the audited statement itself — detection unchanged,
  the dictated figure grounding nothing.
- **R19 — Portfolio views.** The book, read whole:
  `GET /portfolio?as_of=` serves one aggregate view computed
  fresh from the artefacts of record, in five sections —
  exposure by segment; exposure by standing policy outcome
  (pass / fail / blocker failure / not fully evaluable /
  not evaluated, the last named, never folded into pass);
  the covenant watch, open breaches ordered by the cure
  clock with the overdue count stated; the staleness census,
  blocked files named with their blocker inputs and the
  blockers histogrammed by input; and the adverse rollup,
  each memo's latest decision counted once — declines by
  coded ECOA reason, deferrals by coded reason, a superseded
  deferral counting as what it became. Every figure is
  re-performed by an independent walk
  (`verify_portfolio_view`); the gate grades the view against
  a hand-decided book and requires the re-performance to name
  tampered figures section by section. Round 17's access
  policy governs the whole view: the builder runs over the
  caller's visible book only, so an unseen file contributes
  nothing — not to a total, not to a count, not even to the
  file count — and a section whose family the role does not
  hold is withheld in place under its coded reason, the
  refusal recorded. The views are read models: computed fresh
  per request, stored nowhere.
